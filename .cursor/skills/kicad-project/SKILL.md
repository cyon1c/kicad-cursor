# KiCad Project Conventions

## Repository model

- **kicad-cursor** is a toolkit repo — it does not contain board designs.
- Your KiCad project lives elsewhere; set named targets in `kicad-cursor.yaml` (`projects` + `activeProject`).
- Copy `examples/kicad-project-template/` into your project folder for starter metadata.

## Configuration

Read `kicad-cursor.yaml` for:

| Key | Purpose |
|-----|---------|
| `activeProject` | Name of the current board target |
| `projects` | Map of target name → KiCad project folder path |
| `projectDir` | Legacy single-project path (used when `projects` is unset) |
| `symbolLibrary.path` | Shared symbol/footprint library root |
| `symbolLibrary.nickname` | Library nickname in schematics (default: `global`) |
| `kicadCli` | Optional override for kicad-cli path |

Switch targets: `uv run python scripts/manage_projects.py use <name>`

Before multi-step work, read `design.yaml`, `constraints.md`, and `bom-targets.yaml` in the **configured project directory**.

## Project directory layout

```text
my-board/
  my-board.kicad_pro / .kicad_sch / .kicad_pcb
  design.yaml            # intent: rails, blocks, constraints, open questions
  constraints.md         # rules, value-field policy, review gate
  bom-targets.yaml       # symbol → LCSC with selection status
  datasheets/            # PDFs + extracted/<stem>/
  research/<MPN>/        # per-IC overview, pins, passives-required
  design-log/            # decisions, open questions, selections, reviews
  design-context/        # generated by dump-design-context — do not hand-edit
```

## Workflow

The schematic phase is IC-before-passives, and **the user draws the schematic** — agents never edit `.kicad_sch`.

| Phase | Skill |
|-------|-------|
| 1. Architecture, rails, blocks | `@design-consultant` |
| 2. IC intake (LCSC + fetch-part) | `@component-select` mode A |
| 3. Per-IC datasheet research | `@datasheet-research` |
| 4. User draws in KiCad | `@schematic-draw` for briefs |
| 5. Review (context + ERC + values) | `@schematic-review` |
| 6. Passive LCSC finalize | `@component-select` mode B |

Full detail: [docs/workflow.md](../../../docs/workflow.md); authoritative plan: [docs/workflow-plan.md](../../../docs/workflow-plan.md).

## Import missing parts

```powershell
uv run python scripts/run_step.py fetch-part --lcsc-id C80200
```

Runs `easyeda2kicad` from the repo venv and auto-repairs the symbol library via `fix-symbol-lib.py`.

## KiCad 10

- CLI: found on PATH, then the platform default; override with `kicadCli` in config or `KICAD_CLI`
- Config dir: `%APPDATA%/kicad/10.0/` (Windows), `~/Library/Preferences/kicad/10.0/` (macOS), `~/.config/kicad/10.0/` (Linux)
- IPC API only needed for PCB-phase tools
- Paths in `kicad-cursor.yaml` accept forward slashes and `~` on every platform

## Agent rules

1. Read project `design.yaml` when planning multi-step work — not before every atomic step
2. For schematic understanding, run `dump-design-context` and read `<project>/design-context/system-map.md` + `open-questions.md`
3. Execute atomic operations via `@kicad-step` and [steps.yaml](../../../steps.yaml)
4. Do not run ERC/DRC ad hoc unless asked; a formal review always includes ERC
5. Prefer existing library symbols; use `fetch-part` for missing LCSC parts
6. Datasheet PDFs in `<projectDir>/datasheets/`, extracted output in `datasheets/extracted/<stem>/`

## MCP servers

Configured in `.cursor/mcp.json`: single `konnect` server, **read-only in the schematic phase** (see `@konnect`). Use `@kicad-step` for cataloged scripts.
