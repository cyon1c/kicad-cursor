# Usage

kicad-cursor is a **toolkit**, not a project workspace. Your KiCad schematic, PCB, and design metadata live in a separate directory on disk. All scripts and agent skills read that path from configuration.

This page covers tooling and configuration. For the design workflow itself, read **[workflow.md](workflow.md)** (guide) or **[workflow-plan.md](workflow-plan.md)** (authoritative plan).

## 1. Configure your project

Copy the example config:

```powershell
Copy-Item kicad-cursor.yaml.example kicad-cursor.yaml
```

```bash
cp kicad-cursor.yaml.example kicad-cursor.yaml
```

Edit `kicad-cursor.yaml` — forward slashes work on every platform:

```yaml
activeProject: my-board

projects:
  my-board: ~/projects/my-board
  other-board: ~/projects/other-board

symbolLibrary:
  nickname: global
  path: ~/projects/global-kicad-lib
```

`~` is expanded, so the same config shape works on Windows, macOS, and Linux.

`kicad-cursor.yaml` is gitignored — each developer keeps their own paths.

### Managing multiple boards

List, add, and switch named targets without editing yaml by hand:

```powershell
kicad-projects list
kicad-projects use other-board
kicad-projects add lab-board C:/path/to/lab-board
kicad-projects show
```

The active target is stored as `activeProject` in `kicad-cursor.yaml`. Steps and scripts use it unless you override for one command.

### Alternative: environment variables

| Variable | Purpose |
|----------|---------|
| `KICAD_PROJECT` | Named project target from `projects` map |
| `KICAD_PROJECT_DIR` | Path to KiCad project folder |
| `KICAD_SYMBOL_LIBRARY` | Path to shared symbol library root |
| `KICAD_CLI` | Path to `kicad-cli` (optional — found on PATH or in the platform default otherwise) |

Environment variables override the yaml file when set.

### One-off override

Pass `--project` or `--project-dir` to any step that needs a project:

```powershell
kicad-step verify-erc --project other-board
kicad-step verify-erc --project-dir C:/path/to/my-board
```

## 2. Prepare your KiCad project folder

Your project directory should contain:

```
my-board/
  my-board.kicad_pro
  my-board.kicad_sch
  my-board.kicad_pcb
  design.yaml          # intent: rails, blocks, constraints, open questions
  constraints.md       # rules, value-field policy, review gate
  bom-targets.yaml     # symbol → LCSC with selection status
  datasheets/          # PDF datasheets + extracted/ output (see below)
  research/<MPN>/      # per-IC pins and required passives
  design-log/          # decisions, open questions, selections, reviews
  blocks/              # per-block intent (optional)
  design-context/      # generated by dump-design-context — do not hand-edit
```

Copy starter metadata from [examples/kicad-project-template](../examples/kicad-project-template/README.md).

### Datasheets and extracted output

Keep datasheet PDFs in your project folder, not in the kicad-cursor repo. When you run `extract-datasheet`, output is written next to the PDFs:

```text
<projectDir>/datasheets/
  bq25895.pdf
  extracted/
    bq25895/
      index.md
      manifest.yaml
      pages/
      tables/
      images/
```

One `extracted/<pdf-stem>/` directory per source PDF. Agents read `index.md` and `tables/*.yaml` from that folder during `/kicad:datasheet-research` and `/kicad:component-select` — never the raw PDF.

```powershell
kicad-step extract-datasheet --pdf datasheets/bq25895.pdf
kicad-step extract-datasheet --all
```

See [examples/kicad-project-template/datasheets/README.md](../examples/kicad-project-template/datasheets/README.md) for details.

Create the KiCad project in KiCad (`File → New Project`) inside that folder, or open an existing one.

## 3. Open in KiCad and Claude Code

1. **KiCad**: Open your project — you draw the schematic here. Save (Ctrl+S) before asking for a context dump, ERC, or review.
2. **Claude Code**: start `claude` **in your board's folder**. The `kicad` plugin is loaded from anywhere, and
   `kicad-step` targets the folder containing the `.kicad_pro` (otherwise `activeProject` in `kicad-cursor.yaml`).

## 4. Agent workflow

```text
/kicad:design-consultant   → design.yaml, constraints.md, architecture, IC intent
/kicad:component-select A  → LCSC + fetch-part for ICs (bom-targets: ic-locked)
/kicad:datasheet-research  → extract-datasheet → research/<MPN>/ (values, no LCSC)
YOU draw in KiCad    → all passives get value fields; agent never edits .kicad_sch
/kicad:schematic-review    → dump-design-context + verify-erc + value audit + report
/kicad:component-select B  → LCSC for passives (bom-targets: passive-locked)
```

Invoke **one** skill per session:

| Skill | Purpose |
|-------|---------|
| `/kicad:design-consultant` | Requirements, power tree, blocks, IC intent |
| `/kicad:component-select` | LCSC and library — IC mode, then passive mode after review |
| `/kicad:datasheet-research` | Per-IC pins, strapping, required passives |
| `/kicad:schematic-draw` | Drawing briefs for you; agent does not draw |
| `/kicad:schematic-review` | Context dump + ERC + value audit + intent diff |
| `/kicad:design-log` | Append decisions, or catch up on a board |
| `/kicad:kicad-project` | Config, library paths, project conventions |
| `/kicad:konnect` | JLC lookup and read-only context via MCP |
| `/kicad:kicad-step` | Run a single cataloged script |
| `/kicad:design-verify` | Ad-hoc ERC/DRC (only when you ask) |
| `/kicad:pcb-layout` | Deferred — layout phase not defined yet |

Details in [workflow.md](workflow.md).

## 5. Step runner

List available steps:

```powershell
kicad-step --list
```

Run a step (uses `activeProject` from config):

```powershell
kicad-step dump-design-context
kicad-step extract-datasheet --pdf datasheets/bq25895.pdf
kicad-step draw-board-outline
```

See [steps.md](steps.md) for the token-efficient step catalog pattern.

### Optional: shell shortcuts

Put `scripts/bin` on your PATH to call the two most frequent steps from any directory:

```powershell
.\scripts\install-path-commands.ps1        # -Uninstall to remove
```

```bash
./scripts/install-path-commands.sh         # --uninstall to remove
```

The PowerShell version edits your Windows user PATH; the shell version appends a guarded block to your shell profile (zsh, bash, or fish). Either way:

```bash
fetch-part C702003
extract-datasheet --pdf datasheets/bq25619.pdf
```

Open a new terminal after installing.

## 6. What does not belong in this repo

- `.kicad_pro`, `.kicad_sch`, `.kicad_pcb` files
- Board-specific datasheets, BOMs, or fabrication outputs
- Personal library paths hardcoded in committed files

Keep those in your KiCad project directory and reference them via `kicad-cursor.yaml`.
