# KiCad Project Conventions

These are the toolkit's standing rules (formerly an always-on rule). The plugin's hook also hard-blocks edits to
`.kicad_sch`, `.kicad_pcb`, and `.kicad_pro` files.

## Repository model

- **kicad-cursor** is a toolkit repo — it does not contain board designs. Never create or edit `.kicad_pro`,
  `.kicad_sch`, or `.kicad_pcb` files inside it.
- The KiCad project lives elsewhere. Board metadata (`design.yaml`, `constraints.md`, `bom-targets.yaml`,
  `datasheets/`, `research/`, `design-log/`) lives in the **user's project directory**, not in the toolkit.
- Copy `examples/kicad-project-template/` into a project folder only as starter metadata for new boards.

## The user draws schematics

- Agents **never edit** `.kicad_sch` files — placement, wiring, labels, and values are the human's work in KiCad.
- Konnect is **read-only for schematics**: design context and JLCPCB lookup only. Never call `add_schematic_component`,
  wiring, or placement tools.
- Agents produce intent (`design.yaml`), research (`research/<mpn>/`), part identity (`bom-targets.yaml`), and
  reviews — not sheets.

## Selection order: ICs before passives

- After design consultation, only **ICs and electromechanical parts** get LCSC numbers and `fetch-part` imports
  (`status: ic-locked`).
- Passives carry a **value field only** while drawing (`status: value-only`). LCSC numbers for passives are assigned
  **after** schematic review signs off (`status: passive-locked`).

## Workflow — one role per session

Invoke one specialist skill at a time to avoid role bleed:

| Phase | Skill |
|-------|-------|
| 1. Architecture, rails, blocks | `/kicad:design-consultant` |
| 2. IC intake (LCSC + fetch-part) | `/kicad:component-select` mode A |
| 3. Per-IC datasheet research | `/kicad:datasheet-research` |
| 4. User draws in KiCad | `/kicad:schematic-draw` for briefs |
| 5. Review (context + ERC + values) | `/kicad:schematic-review` |
| 6. Passive LCSC finalize | `/kicad:component-select` mode B |
| Session continuity notes | `/kicad:design-log` |

Full detail: [docs/workflow.md](../../docs/workflow.md); authoritative roles, gates, and artifacts:
[docs/workflow-plan.md](../../docs/workflow-plan.md).

## Which project? (configuration)

`kicad-step` resolves the target board in this order: `--project-dir` → `--project` → `KICAD_PROJECT_DIR` →
`KICAD_PROJECT` → `activeProject` in `kicad-cursor.yaml` → legacy `projectDir`.
When run from inside a folder containing a `.kicad_pro`, `kicad-step` sets `KICAD_PROJECT_DIR` to that folder.

`kicad-cursor.yaml` (in the toolkit repo, gitignored) holds:

| Key | Purpose |
|-----|---------|
| `activeProject` | Name of the current board target |
| `projects` | Map of target name → KiCad project folder path |
| `projectDir` | Legacy single-project path (used when `projects` is unset) |
| `symbolLibrary.path` | Shared symbol/footprint library root |
| `symbolLibrary.nickname` | Library nickname in schematics (default: `global`) |
| `kicadCli` | Optional override for kicad-cli path |

Switch targets: `kicad-projects use <name>`

Before multi-step work, read `design.yaml`, `constraints.md`, and `bom-targets.yaml` in the **project directory**.
Never hardcode absolute or platform-specific paths in committed files — use `kicad-cursor.yaml`, env vars, or `pathlib`.

## Project directory layout

```text
my-board/
  my-board.kicad_pro / .kicad_sch / .kicad_pcb
  design.yaml            # intent: rails, blocks, constraints, open questions
  constraints.md         # rules, value-field policy, review gate
  bom-targets.yaml       # symbol → LCSC with selection status
  datasheets/            # PDFs + extracted/<stem>/
  research/<MPN>/        # per-IC overview, pins, passives-required
  design-log/            # decisions, open questions, selections, reviews
  design-context/        # generated by dump-design-context — do not hand-edit
```

## Running steps

All cataloged operations go through `kicad-step` (`/kicad:kicad-step`, catalog in [steps.yaml](../../steps.yaml)).
Do not explore kipy or MCP for operations that have a step.

```bash
kicad-step --list
kicad-step fetch-part --lcsc-id C80200   # easyeda2kicad + auto-repair via fix-symbol-lib
```

Datasheet PDFs go in `<projectDir>/datasheets/`; extracted output in `<projectDir>/datasheets/extracted/<pdf-stem>/`.
For schematic understanding, run `dump-design-context` and read `<project>/design-context/system-map.md` +
`open-questions.md`.

## Symbol library

- Import parts with `fetch-part` into the library configured in `kicad-cursor.yaml` (`symbolLibrary.path`).
- Prefer existing library symbols; `fetch-part` only for missing LCSC parts.

## Verification

- Do not run ERC/DRC ad hoc unless the user asks or invokes `/kicad:design-verify`.
- **Exception:** a formal schematic review (`/kicad:schematic-review`) always runs `verify-erc` — a review without ERC
  output is incomplete.
- ERC and DRC read the **saved** files on disk — remind the user to Ctrl+S in KiCad first.

## KiCad 10

- CLI: found on PATH, then the platform default; override with `kicadCli` in config or `KICAD_CLI`
- Config dir: `~/.config/kicad/10.0/` (Linux), `~/Library/Preferences/kicad/10.0/` (macOS), `%APPDATA%/kicad/10.0/` (Windows)
- IPC API (Preferences → Plugins → Enable IPC API Server) is only needed for PCB-phase tools

## MCP server

The plugin's `.mcp.json` starts a single `konnect` server, **read-only in the schematic phase** (see `/kicad:konnect`).
